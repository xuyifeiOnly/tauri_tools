# 随享

新生成的 SSH 密钥注释为 `suixiang-xyf-key`（仅识别标签，不是登录账号）；已有及导入密钥的注释不自动修改。

原名Mac Tunnel，现统一显示为“随享”。内部应用标识`cn.rutang.mac-tunnel`和数据目录保持不变，已有配置、密钥及主机信任继续使用。

## 安装与升级

GitHub macOS ZIP打包前会对完整.app进行临时签名并严格校验，解压回读后再次验签，避免仅有linker签名的无效应用包。临时签名不是Developer ID签名或Apple公证，不能保证下载后Gatekeeper放行；0.1.4已发现完整bundle签名无效，需使用修正工作流重新构建，不能将“已损坏”一概当作下载不完整。

macOS 源码补充 Dock 图标点击的 `RunEvent::Reopen`，恢复隐藏/最小化的已有主窗口并聚焦，不创建新窗口或重启共享；需更新安装生效，Dock 原生点击仍待验收。

源码已加入应用级单实例保护（Tauri single-instance）：重复启动会唤起已有主窗口，隐藏窗口会显示、最小化窗口会还原并聚焦，不再创建第二套配置/托盘/服务。托盘“打开随享”复用相同行为。需更新安装后生效；首次升级前请从各旧实例托盘正常退出，旧版本已启动的多个实例不由新版本自动清理。单实例不代表任务管理器中只有一个进程：WebView 和 SSH 子进程仍属正常。Windows 原生多开/唤起行为仍待实机验收。

运行`./scripts/app_install.sh`构建安装，默认patch版本+1；重复安装相同版本使用`--keep-version`。固定安装到`/Applications/随享.app`。成功后注销并移除本项目debug/release打包副本，以及应用目录中经标识核验的旧名/重复应用，只注册安装版，不留下可被系统再次扫描的构建.app或永久备份。临时替换备份成功即删除；清理失败明确报错。可用`python3 scripts/test_app_install.py`运行安全清理回归。

`--no-install`或直接调用Tauri打包只生成构建产物，不执行安装后去重，因此可能重新出现同标识副本；日常升级请使用安装脚本。不会扫描任意磁盘位置，也不保证清理由用户手动复制到其他位置的应用。

2026-11-25已安装0.1.2并完成同版本重复安装，限定范围内仅一个.app、LaunchServices仅一条注册；未自动启动共享，启动台视觉刷新未单独验收。仍为未Developer ID签名/公证的本机测试包。

macOS 本地目录共享客户端，Tauri 2 + Vue 3 + Rust。当前为首个开发预览版，尚非正式安全审计或公网验收版本。

应用图标以文件夹和向外的连接箭头表达目录通过隧道共享。Dock 与侧栏使用 `src-tauri/icons/mac-tunnel.svg` 生成的彩色 PNG/ICNS；macOS 菜单栏单独使用透明单色的 `tray-template.svg` / `tray-template.png`，并启用模板图标，使系统按菜单栏外观自动显示白色或深色。

## 运行

```bash
bun install
bun run tauri dev
```

打包：`bun run package`（或 `./scripts/package.sh`），默认 release 并自动递增 patch 版本；需要 debug 时用 `./scripts/package.sh --debug`。产物位于 `src-tauri/target/<release|debug>/bundle/macos/随享.app`。构建依赖 Rust、Xcode Command Line Tools 和 Bun。只运行 `bun run dev` 是无后端界面预览，不能控制服务。

### Windows 构建

仅更新版本（不打包、不安装）：`bun run version:bump` 默认补丁号 +1；指定版本使用 `bun run version:bump --version 0.2.0`；预览使用 `bun run version:bump --dry-run`。脚本 `scripts/bump-version.ts` 同步 package.json、Tauri 配置和 Cargo.toml，可在任意工作目录用脚本绝对路径运行。更新后若本地打包不想再次增版，请用 `./scripts/package.sh --keep-version`；Cargo.lock 由后续 Cargo 构建更新。

Windows 安装包（`.exe`）**不能在 macOS 上交叉编译**：`ring` 等 C 依赖需要 MSVC 工具链和 Windows SDK，macOS 上只能编译到链接阶段前。请使用仓库自带的 GitHub Actions 工作流 `.github/workflows/build.yml`，在 `windows-latest` 原生 runner 上构建 NSIS 安装包：

- 推送 `v*` 标签（如 `v0.1.2`）自动构建，并把安装包**直接附加到同名 GitHub Release**：Windows 为 `suixiang_<版本>_windows_x64.zip`，解压后运行其中的 `随享_<版本>_x64-setup.exe` 安装（不是免安装版）；macOS 为 `随享-macos.zip`。若 Release 尚不存在会自动创建。
- Windows ZIP 在上传前自动解压并核对安装程序 SHA-256，Release 仅上传 ZIP。包装 ZIP 不等于解决安装程序损坏或安全拦截；同版本重跑不会自动删除此前已发布的旧 `.exe` 附件。
- 手动触发（**Actions → build → Run workflow**）同样发布 Release：选择待构建分支，使用该分支源码版本号生成标签（当前为 `v0.1.2`），两个平台都构建成功后上传安装包，到仓库 **Releases → 对应版本 → Assets** 下载。Actions artifact 仍保留。
- `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 版本必须一致，推送标签也必须与源码版本一致；工作流不自动递增版本。相同版本重跑会更新同名附件，发布新版本请先更新源码版本。已有标签不会移动，建议仅重跑同一提交；新版本使用新版本号。
- 工作流通过内置 `GITHUB_TOKEN` 发布，无需额外密钥；只有发布 job 具有 `contents: write` 权限。构建包未配置正式代码签名/macOS 公证，macOS 仅当前 runner 架构，不是通用包。
- 本地 Windows 也可直接 `bun install && bunx tauri build --bundles nsis`。

跨平台适配：SSH/ssh-keygen/ssh-keyscan 路径、打开浏览器、私密权限、局域网地址枚举集中在 `src-tauri/src/platform.rs`；macOS 专属的孤立 SSH 检查在 Windows/Linux 上自动跳过。Windows 需系统自带 OpenSSH 客户端（Windows 10/11 默认已安装）。

## 使用

### 共享目录浏览（源码，需更新安装生效）

共享首页和目录列表使用内置蓝灰文件浏览器样式，无 CDN 或页面脚本：彩色 SVG 类型图标、文件名/类型/大小、文件夹优先排序、面包屑和返回上级。首页显示目录访问保护，亮暗主题跟随系统；手机隐藏次要类型列，密码标记保留，长文件名完整换行。仅只读浏览，不提供上传或删除；分享地址、认证/LAN隔离、HTML index首页优先和Markdown/TIFF预览行为不变，不展示本机绝对路径。新样式需重新构建安装后生效。

### Markdown 阅读预览（源码，需更新安装生效）

本地共享的 `.tif/.tiff` 图片默认由服务端转换为 PNG 预览，Markdown 中的原图片路径无需修改，也不会覆盖原 TIFF。`图片地址?raw=1` 返回原文件，`图片地址?download=1` 下载原 TIFF（支持 Range）。多页仅展示第一页；不转换远程 TIFF。输入上限16MiB、宽高各8192、总像素1600万、解码分配预算128MiB（库尽力限制，非进程硬上限），最多两个并发转换；超限413、损坏/不支持422、繁忙503。转换结果不落盘、不缓存，所有模式沿用目录权限。完整应用需重新打包安装生效。

共享 `.md` / `.markdown` 链接默认显示阅读页面，支持标题、表格、任务列表、删除线、图片及代码语法高亮；扩展名大小写不敏感。相对图片按文档目录解析，兼容公网前缀，仍需满足所属共享目录的访问权限。支持 HTTP/HTTPS 远程图片，但不代理远程资源，HTTPS 页面中的 HTTP 图片可能被浏览器拦截。

阅读页提供“查看源码”（`?raw=1`）及“下载原文件”（`?download=1`），不修改磁盘文件；原文件模式仍支持 Range。排版、解析与代码高亮均随应用内置，不依赖 CDN，自动适配系统亮暗与手机。使用 pulldown-cmark、syntect、ammonia，移除文档原始 HTML，清洗危险链接并设置预览专用 CSP；不支持文档脚本、内嵌 HTML 图片、Mermaid 或公式。请使用标准 Markdown 图片语法 `![说明](images/photo.png)`。

UTF-8 文件预览上限 2 MiB；超限/其他编码提供说明及原文件入口。单个代码块超过 64 KiB 时按普通代码显示，未知语言同样不高亮。可运行 `cargo run --manifest-path src-tauri/Cargo.toml --example markdown_preview` 启动独立临时目录、随机回环端口的验证服务（Ctrl+C 停止），不连接 SSH，不操作现有共享。

### Windows SSH 后台运行与重连排查

源码已统一后台启动 SSH、密钥及网络查询工具，在 Windows 使用 CREATE_NO_WINDOW，避免连接/重连弹出终端；需要重新构建安装才生效。SSH 退出日志保留退出码及错误，远端转发绑定失败补充端口冲突提示。此修复不代表所有断线原因均已解决。

多台设备不能同时占用同一服务器的同一个转发端口（如 18790）；各设备需使用独立端口，服务端代理也需对应配置。不要为了恢复 Windows 而随意停止其他设备的隧道。持续重连请提供“运行日志”中的 SSH 退出错误，不包含私钥或密码。

### 共享工作台（当前源码，未安装）

概览按本地服务、SSH 隧道、公网验证显示状态和当前可用操作。无可用目录时先添加目录；仅本机或局域网共享不需要配置 SSH。手动验证入口位于公网状态旁，并显示当前连接上次探测时间。

目录映射先选择目录，再设置名称、路径与访问范围。分享地址区区分本机、局域网、公网，使用已保存配置；公网链接仅在验证可达后可用。浏览文件也使用已保存目录。连接配置区分本地服务、可选公网连接和高级设置。

无修改时不能保存。运行中保存配置或密码会停止本客户端的共享，底部提供手动重新启动本地服务；公网隧道需手动重连。以下旧版操作记录中的按钮名称和位置以此节为准。

连接公网前源码新增旧SSH检查：先回收当前任务，再按真实argv完整匹配本应用命令，仅自动TERM同用户、PPID1的孤立旧隧道并最多等待5秒；其他客户端管理的相同连接提示冲突，不自动结束。参数无法核验或停止失败不启动新SSH。不会模糊匹配/批量结束SSH，不清理不同配置或远端未知进程。检查结果记入日志；此功能尚未覆盖安装及真实孤立SSH清理验收。

概览“打开本地目录入口”源码已改为调用系统浏览器打开（与目录映射复用openAddress），不再依赖WebView的target=_blank；打开失败显示错误。若升级后重连等待，应先查看日志并区分升级前孤立SSH与当前客户端子进程，不可泛杀SSH。本轮曾清理确认的升级前旧进程后恢复公网，不能据此判断新版退出回收失效。

右上角“验证公网”可手动触发健康检查，验证中禁用重复点击并显示结果提示。需先启动本地服务并连接SSH。每次SSH进程启动后约3秒首次检查，后续自动检查间隔为10分钟；手动检查完成后重新计时。界面状态刷新和SSH心跳频率不变。检查结果是上次探测结果，不代表两次探测间持续可达。

部署助手确认主机信任保存成功后，按钮显示绿色勾选“已确认信任”并禁用重复提交；保存失败不显示成功。重新读取指纹或修改主机/端口会清除本次确认显示。当前显示仅在当前面板有效，不代表重新打开面板后已从磁盘恢复信任状态。

连接持续“重连等待”时先查看运行日志并检查服务器转发端口是否被旧SSH占用；不要重复建立相同端口的隧道或批量结束SSH。Nginx文件已配置不代表运行配置生效，需检查语法并平滑重载；公网可用应以健康实例标识与本机一致为准。2026-11-25已完成一次真实HTTP公网目录/PDF访问验证，仍不代表HTTPS或长期稳定性已验收。

源码已增加SSH生命周期清理：断开、重新连接、保存配置及正常退出均等待本客户端SSH子进程终止并回收，取消退避和健康请求后再返回；托盘退出、Cmd+Q及系统正常退出统一清理。关闭窗口仍只隐藏；不会扫描或批量结束其他SSH。SIGKILL/崩溃不保证清理，远端端口释放也可能有网络延迟。当前修复通过本地假进程测试，尚未覆盖安装或原生退出实测，旧安装需更新后生效。

概览状态：异常为红色，运行中/公网确认可访问为绿色，连接和重连为黄色，未启动/未检查为中性色。SSH进程运行不等于公网可访问。已修复macOS应用数据目录含空格时SSH无法读取已信任主机指纹文件的问题，仍保留严格主机校验；旧安装版本需更新客户端才能生效。

桌面窗口采用固定导航和顶栏，不整页滚动。连接表单、目录列表、密钥列表各自滚动，保存操作保留在面板底部；部署脚本与运行日志在各自区域滚动。长路径和密钥指纹不会撑宽窗口；滚动区域可通过Tab聚焦后用键盘滚动。

连接表单长密钥选择项限制在列内，避免横向撑宽；内容放得下时不保留空滚动槽，内容较多时仍可纵向滚动查看后台运行。输入框与下拉框采用统一主题色焦点边框，滚动区域留出完整显示高亮的内边距。此样式修复尚未覆盖安装版。

### 首次准备Linux服务器

修改 `scripts/service.sh` 顶部的账号、可选账号密码、Mac公钥、转发端口、域名及前缀，上传到服务器后执行 `sudo bash service.sh`。无交互，直接准备；只需要公钥，不上传私钥。缺少依赖时停止并提示，不自动安装软件。账号密码留空则无可用密码，填写后也不允许SSH密码登录；切勿将真实密码提交Git，执行后妥善保管或删除服务器脚本。

安装前检查目标账号的配置标记：已配置则跳过创建和凭据修改；账号存在但无标记则停止，避免接管其他隧道。首次创建账号、公钥和SSH规则并重载；不改变SSH端口、不修改防火墙、不停止既有隧道。SSH主配置修改前保存恢复副本；失败可能已创建账号/公钥，不能视为全部回滚。其他账号已有隧道不代表此账号已配置，也不能代表指定转发端口可用。

**Nginx只输出带注释片段**，人工放入已有HTTPS server中，然后手动 `sudo nginx -t && sudo nginx -s reload`。脚本每个操作行均有注释，生成SSH规则使用前置注释避免解析歧义。

按脚本最后输出在Mac客户端配置并连接，再检查服务器回环监听、回环健康端点及公网健康端点，公网返回的实例标识须与Mac本地一致，最后实际访问受保护文件。已移除交互和独立`--check`模式；重复运行会跳过已有账号配置并检查有效SSH权限。SSH权限检查不等于真实认证成功；AllowUsers/AllowGroups/PAM等可能仍需管理员调整。

依赖Linux/systemd、已有OpenSSH（目标兼容7.4，尚未在7.4实测）。旧版不能按远端端口精确限权，专用账号仅供可信设备使用。脚本不会安装或自动配置HTTPS，未完成公网验证不能称为开通完成。

### 目录浏览与局域网访问

目录映射中的“本地打开 / 复制本地地址”使用电脑局域网IPv4，不再使用127.0.0.1。单IP直接操作，多IP点击后选择；每次操作重新查询接口。需要目录已启用并允许LAN、相关目录配置已保存、本地服务已启动；修改LAN设置需保存并重启。未检测到IP明确报错，不回退为回环地址。概览回环入口保持不变。此源码改动尚未覆盖安装。

目录列表收起为紧凑行，每行“浏览文件”打开只读目录树，文件夹按需展开，普通文件可复制链接。须先保存配置；隐藏文件、敏感密钥、符号链接及特殊文件不展示，每层最多5000项。

每个目录独立设置“允许局域网访问”，默认关闭，保存后重新启动本地服务生效。只有至少一个启用目录允许LAN时才监听IPv4全部接口；非回环请求仅能访问获准目录，仍受目录密码保护，入口列表不展示其他目录。SSH反向转发仍经回环访问。局域网HTTP不加密，勿在不可信网络开放。

文件树使用彩色SVG区分文件类型，36px紧凑行，每文件提供28px的“局域网”“公网隧道”独立复制按钮。顶部不常驻展示地址；局域网复制需要开启该目录LAN访问，多网卡仅点击后选择IP，单网卡直接复制。公网复制使用公网源站及访问前缀，要求状态已确认公网可访问，两种渠道互不替代。中文/空格等逐段编码；防火墙、网络隔离及网页内部绝对路径仍可能影响其他设备访问，不保证任意网络直达。

### 一键打包安装（本机测试）

```bash
./scripts/app_install.sh                     # 补丁版本 +1、release打包、安装到 /Applications
./scripts/app_install.sh --version 0.2.0      # 指定版本，其他行为同上
./scripts/app_install.sh --keep-version      # 保持版本，重新构建安装
./scripts/app_install.sh --debug             # 改为 debug 构建安装
./scripts/app_install.sh --release --open    # release构建安装后启动（release 已是默认）
./scripts/app_install.sh --no-install       # 仅更新版本和打包
./scripts/app_install.sh --dry-run --no-install # 预览版本和打包路径，不写入
```

默认构建 release 并默认递增 patch 版本；只有显式 `--debug` 或 `./scripts/package.sh --debug` 才生成 debug 包。
